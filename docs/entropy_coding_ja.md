# なぜ「エントロピー符号化」と呼ぶのか

学習導線: [learn_ja.md](learn_ja.md) · 関連: [rice_ja.md](rice_ja.md) · [dc_coding_ja.md](dc_coding_ja.md) · [用語集](glossary_ja.md)

## この文書の結論

**情報理論のエントロピー H は「1 記号あたり最短で何ビット必要か」の理論下限です。
その下限に近づける符号化を総称してエントロピー符号化と呼び、BPE の Rice はその一種です。**

物理で習う「乱雑さ」のエントロピーとは、式の形は似ていても、ここで測っている対象が違います。

## 絵で見る

```text
記号の出やすさ（確率）
        |
        v
  エントロピー H ＝「平均でこれ以下には縮められない」下限
        |
        v
  エントロピー符号化（Huffman / 算術符号 / Rice …）
        |  よく出る → 短く
        |  稀な    → 長く
        v
  実際の平均ビット長 ≈ H（近づけたい）
```

BPE での位置:

```text
DC:  量子化 → DPCM → mapped（小さい数に偏る）→ Rice  ← ここがエントロピー符号化
AC:  走査シンボル / depth など               → Rice  ← 同様
```

## 詳細

### 1. 物理のエントロピーと何が違うか

| | 物理（統計力学） | 情報理論（シャノン） |
|--|--|--|
| 対象 | 系の微視的状態の数・乱雑さ | 記号（値）の **出方の偏り** |
| 直感 | 熱・無秩序が増える | よく出る値は短く書ける |
| 単位のイメージ | J/K など | **ビット／記号** |

シャノンは「似た形の式がある」としてこの語を借りました（フォン・ノイマンの助言という話が有名です）。
**熱統計力学の公式をそのまま使っているわけではありません。**

### 2. エントロピー H は「縮められる限界」

記号 i が確率 p_i で出るとき、情報理論のエントロピーは次の通りです。

```text
H = Σ p_i · log2(1 / p_i)     （ビット／記号）
```

log2(1 / p_i) がポイントです。

- **よく出る**（p_i 大）→ log2(1/p_i) 小 → **短いビットを割り当てるべき**
- **稀**（p_i 小）→ log2(1/p_i) 大 → 長いビットでよい

H は、「確率に応じてビット長を最適に割り振ったときの、達成できる **平均ビット数の下限**」を表す 1 つの数字です。

### 3. だから「エントロピー符号化」と呼ばれる

発想を逆にします。

> H が理論的な最短の平均ビット数なら、
> **実際にそこへ近づける符号化**を作ればいい。

その「H が示す下限に近づけることを目的にした符号化」の総称が
**エントロピー符号化（entropy coding）** です。

仲間の例:

- Huffman 符号
- 算術符号 / レンジコーダ
- **Rice / Golomb 符号** ← BPE で使うもの

個々の手法名（Rice）とは別に、**分類名**として「エントロピー符号化」と呼ばれます。
目標がエントロピー H だから、という命名です。

### 4. 数値の直感

4 種類の値 A, B, C, D を送るとします。

**均一（偏りなし）** 各 1/4:

- H = 2 ビット／記号
- 2 ビット固定（00, 01, 10, 11）で最適。**これ以上は縮められない。**

**偏りあり** A=1/2, B=1/4, C=1/8, D=1/8:

- H = 1.75 ビット／記号
- 例: A→`0`, B→`10`, C→`110`, D→`111` で平均も約 1.75 ビット
- 固定 2 ビットより短い。**偏りがあるほど H は小さく、縮む余地が生まれる。**

エントロピー符号化とは、この「偏りに応じたビット長の割り当て」を実現する技術です。

### 5. なぜ BPE のパイプラインに出てくるか

DWT → 量子化 → DPCM までで「何を送るか」は決まりますが、まだ
**整数の列をビット列にする**必要があります。その最後の詰めがエントロピー符号化です。

BPE ではだいたい次の流れです。

1. DC: 量子化 → 隣接差分（DPCM）→ 非負整数へ写像
2. 小さい数が多くなる（幾何分布／ラプラス分布に近い）
3. **Rice / Golomb-Rice** で、その偏りに合わせて短く書く

実装では `dc/entropy.rs` の `dc_entropy_encoder` など、
「Rice する段」をまとめて **エントロピー（符号化）** と呼んでいます。
Rice の使い方そのものは [rice_ja.md](rice_ja.md) を見てください。

### 6. 一言でまとめると

> **エントロピー H＝縮められる限界（平均ビット数の下限）。
> その限界に近づけるのが目的の符号化だから「エントロピー符号化」と呼ぶ。**

物理の乱雑さの話ではなく、「この限界まで縮めたい、という目標値の名前」だと捉えると、
名前の理由がはっきりします。
