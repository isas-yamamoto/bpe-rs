# 具体例で追う BPE（ハンズオン）

> 学習導線: [入口（learn_ja）](learn_ja.md) · 次は [全体地図（algorithm_ja）](algorithm_ja.md)


## この章の結論

**数値例で「周波数に分ける→DC先→重いビットからAC」の感覚を先につかみます。**

用語: [用語集](glossary_ja.md)

## 絵で見る

```text
2x2画素 -> 平均と差 -> DC先送 -> ビットプレーン
```

## 詳細

この文書は、**数値を手で追いながら** BPE が何をしているかを体感するための章です。
実装の関数名や全パラメータは後回し、ここでは「画像がどう変わるか」だけ見ます。

完全な実装とは異なる **教材用の簡略例** です。
数字は手計算しやすいように選んであり、本物の「感覚」をつかむためのものです。

---

## 0. この章で分かること

読み終わったら、次の 4 つを説明できるはずです。

1. **なぜ** 画像を周波数に分けると圧縮しやすいか
2. **どう** 8x8 ブロックが「親・子・孫」の木になるか
3. **どう** [DC](glossary_ja.md)（大まかな明るさ）を先に送るか
4. **どう** AC を「重いビットから」送るか（[ビットプレーン](glossary_ja.md)）

所要時間の目安: **20〜30 分**。

---

## 1. 出発点: とても小さな「画」

本物は幅・高さが 8 の倍数の画像を使いますが、ここでは考えやすく **2x2 の画素** から始めます。

```text
画素値（明るさ 0〜255 のうち）:

  100  104
  102  108
```

隣の画素が似ています。そのまま送ると 8 bit x 4 = 32 bit 必要です。
「似ている」という情報を使えば、もっと短くできそうです。

---

## 2. ウェーブレットの感覚（超簡易版）

「平均」と「差」に分けます。行ごとに見ると:

```text
1 行目: 100 と 104
  平均的な値 ≈ 102
  差（右 - 左）  =  +4

2 行目: 102 と 108
  平均的な値 ≈ 105
  差               =  +6
```

さらに列方向でも同様に分けると、大まかに次のような四つの数が出来ます。

```text
  LL（大まかな明るさ）   HL（横方向の差）
  LH（縦方向の差）       HH（斜めの差）
```

教材用の仮の数値例（本物の 9/7 とは異なる計算）:

```text
  LL = 104
  HL =   3
  LH =   2
  HH =   1
```

### なぜ圧縮しやすいか

- **LL** は 1 個だけで、画の大まかな明るさを表す
- **HL / LH / HH** は小さい（ここでは 1〜3）
- 小さい数は、後で出てくる **ビットプレーン** で「無視しても画質が落ちにくい」

本物ではこれを **3 段** 繰り返し、LL をさらに細くします（そのため幅・高さが 8 の倍数必要）。
詳細: [lifting97_ja.md](lifting97_ja.md)

---

## 3. 8x8 ブロック = 「1 場所の全周波数」

本物では、同じ空間位置の係数を **8x8 ブロック** にまとめます。
左上が DC（= LL3）、残りが AC です。

```text
+----+----+--------+
| DC | P  |  C0    |   P = 親（レベル3）
|    |    | (2x2)  |   C = 子（レベル2）
+----+----+--------+   H = 孫（レベル1）
|  C1    |  C2    |
| (2x2)  | (2x2)  |
+--------+--------+
|     H (4x4)     |
+-----------------+
```

親が小さい（ほぼ 0）なら、子や孫も小さいことが多い。
この「意外と無い」を使って、後で **枝刈り**（[TranB](glossary_ja.md)=0 なら子孫を読まない）します。

詳細: [coeff_group_ja.md](coeff_group_ja.md) / [block_scan_ja.md](block_scan_ja.md)

---

## 4. DC を先に送る

各ブロックの **DC** は、その場所の「平均的な明るさ」です。
これを先に送れば、復号側はすぐに **ぼやけた画** を持てます。

仮の 4 ブロックの DC:

```text
ブロック:  A    B    C    D
DC:         100  104  102  108
```

### ステップ A: 量子化（低位を切る）

例: `q = 2`（右に 2 ビットシフト）

```text
shifted = DC >> 2
A: 100 >> 2 = 25
B: 104 >> 2 = 26
C: 102 >> 2 = 25
D: 108 >> 2 = 27
```

切り捨てた低位は、後で余裕があれば送ることもあります。

### ステップ B: 差分にする（[DPCM](glossary_ja.md)）

隣との差は小さいことが多いので、**差分** にします。

```text
A: 25（基準、そのまま）
B: 26 - 25 = +1
C: 25 - 26 = -1
D: 27 - 25 = +2
```

さらに非負整数へ写像（正は偶数、負は奇数、という zigzag）:

```text
mapped:
A: 25（生値のまま送る）
B: +1 → 2
C: -1 → 1
D: +2 → 4
```

### ステップ C: [Rice](glossary_ja.md) で圧縮

小さい数（2, 1, 4）が多いので、Rice 符号が効きます。
例: `k = 1` のとき

```text
v = 2, k = 1
  商 q = 2 >> 1 = 1
  余り r = 2 & 1 = 0
  出力 ≈「1 が q+1 個」+ 「r を k ビット」
         = 11 0
```

小さい v ほど短いコードになる、というだけ覚えてください。
詳細: [dc_coding_ja.md](dc_coding_ja.md) / [rice_ja.md](rice_ja.md)

## 5. AC を「重いビットから」送る

ここが BPE の中心です。

### 5.1 整数の振幅を 2 進数で見る

仮の AC 係数（すでに整数化済み）:

```text
  v = 13   （二進: 1101）
  |v| のビット:
    ビット位 4: 1   ← 最も重い
    ビット位 3: 1
    ビット位 2: 0
    ビット位 1: 1   ← 最も軽い
```

BPE は **ビット位 4 → 3 → 2 → 1** の順で送ります。

> **注意**: 浮動小数 [DWT](glossary_ja.md)（`-t 0`）でも、丸め後の **整数振幅** に対する操作です。
> IEEE 754 のビット列を送っているわけではありません。

### 5.2 「初めて 1 が立ったプレーン」が重要

| プレーン | 振幅 13 のビット | 意味 |
|----------|------------------|------|
| 4 | 1 | **初めて有意**。符号(+/-)も一緒に送る |
| 3 | 1 | すでに有意なので **refine**（精度を一段細く） |
| 2 | 0 | refine |
| 1 | 1 | refine |

レートが足りなければ、軽いプレーンで止めても、「そこに係数がある」こと自体は伝わっています。
これが **重いビットから送る利点** です。

### 5.3 森を走査して、無い枝を切る

1 プレーンの中では、次の順で走査します。

```text
1. TypeP   -- 親 3 個は有意か？
2. TranB   -- 子孫のどこかに有意があるか？
   + TranB = 0 なら、このブロックの残りは全部スキップ
3. TypeCi  -- 子を個別に見る
4. TypeHij -- 孫を個別に見る
```

仮の例（プレーン 4）:

```text
親 P0=13（有意）, P1=0, P2=0
子・孫は全部 |v| < 8 なので、プレーン 4 では無意

-> TypeP:  1 0 0 (+ 符号)
-> TranB:  0     <- 子孫なし、残り全省略
```

「無いと分かったら送らない」。これがゼロツリー系の強みです。

詳細: [block_scan_ja.md](block_scan_ja.md) / [ac_stages_ja.md](ac_stages_ja.md)

## 6. 一通りの回顧

```text
画像
  |  ウェーブレット（平均と差に分ける）
係数
  |  8x8 にまとめる（DC + 親・子・孫）
ブロック
  |  DC を先に送る（量子化 -> 差分 -> Rice）
ぼやけた画が復号側に届く
  |  AC を重いビットから送る
     （有意になった場所だけ、無い枝は切る）
細部が徐々に明確に
```

レートが足りなければ、軽いビットの途中で止めても
「ぼやけた画 + 大きな特徴」は残ります。
